# ESP32-S3 单音基频与音符识别方案

根据你们目前的硬件条件，建议先实现一个类似于电子调音器的嵌入式系统：通过麦克风实时采集声音，估计声音的基频，识别对应音符，并计算音高偏差。

现有硬件足以完成这个课题，不需要额外的音频处理芯片。OLED 可以等核心算法实现后再接入。

## 一、项目目标

建议将基础版本的技术指标设定如下，作为开发和验收目标。

| 指标 | 设计目标 |
| --- | --- |
| 输入信号 | 哨音、哼唱、单音乐器声 |
| 输入限制 | 同一时刻只有一个主音 |
| 基频识别范围 | 80～2000 Hz |
| 采样率 | 16000 Hz |
| 音符识别体系 | 十二平均律 |
| 标准参考音 | A4 = 440 Hz |
| 音高偏差单位 | 音分（Cent） |
| 稳定输入下的音高精度 | ±5 Cent |
| 结果刷新频率 | 约 10 Hz |
| 初期显示方式 | USB 串口 |
| 最终显示方式 | OLED 屏幕 |

以上指标是预期目标，并非已经实测得到的性能。

## 三、硬件设计

### 3.1 硬件组成

| 硬件 | 数量 | 用途 |
| --- | ---: | --- |
| ESP32-S3-DevKitC-1 | 1 | 信号采集、算法运行 |
| INMP441 | 1 | 数字音频采集 |
| OLED 屏幕（建议 SSD1306，128×64） | 1 | 显示音符及音高偏差 |
| 杜邦线 | 若干 | 模块连接 |
| USB 数据线 | 1 | 供电、程序下载及串口调试 |

INMP441 本身就是数字麦克风，内部集成了模数转换功能，因此不需要使用 ESP32 的 ADC，直接通过 I2S 接口读取音频数据即可。

### 3.2 INMP441 接线方案

建议采用下列 GPIO 分配：

| INMP441 引脚 | ESP32-S3 引脚 | 功能 |
| --- | --- | --- |
| VDD | 3.3V | 电源 |
| GND | GND | 地线 |
| SCK | GPIO 4 | I2S 位时钟 |
| WS | GPIO 5 | I2S 声道选择 |
| SD | GPIO 6 | 音频数据输入 |
| L/R | GND | 选择左声道 |

注意：

- INMP441 使用 3.3V 供电，不要直接连接 5V。
- L/R 接地后，软件需要读取对应的左声道数据。
- 上述 GPIO 为建议分配，并非固定要求。
- I2S 读取时采用 32 位时隙承载麦克风的 24 位有效音频数据。

### 3.3 OLED 预留接线

后续可以使用 I2C 接口的 OLED 屏幕。

| OLED 引脚 | ESP32-S3 引脚 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO 8 |
| SCL | GPIO 9 |

I2S 与 I2C 使用不同的引脚，两者可以同时运行。

## 四、基频识别算法选型

### 4.1 什么是基频？

真实乐器声和人声往往不是单一频率的正弦波，而是由基频和多个谐波共同组成的。

例如，一个 A4 音符可能包含：

| 成分 | 频率 |
| --- | ---: |
| 基频 | 440 Hz |
| 二次谐波 | 880 Hz |
| 三次谐波 | 1320 Hz |
| 四次谐波 | 1760 Hz |

其中，440 Hz 才是我们真正需要识别的音高。

有时谐波的幅度甚至会超过基频，因此不能简单地认为频谱中幅度最大的频率就是基频。

### 4.2 算法对比

| 算法 | 实现难度 | 抗谐波能力 | 实时性 | 推荐程度 |
| --- | --- | --- | --- | --- |
| 过零检测法（ZCR） | 低 | 较弱 | 高 | ★★ |
| FFT 最大峰值法 | 较低 | 较弱 | 高 | ★★★ |
| 谐波乘积谱（HPS） | 中 | 较好 | 高 | ★★★★ |
| 自相关法（ACF） | 中 | 较好 | 较高 | ★★★★ |
| YIN 算法 | 中 | 较好 | 较高 | ★★★★★ |

推荐使用 YIN 算法作为最终的基频识别算法。

主要原因：

- 适用于哼唱、哨音和单音乐器声。
- 相比直接寻找 FFT 峰值，更不容易受到谐波干扰。
- 不需要训练数据集或机器学习模型。
- 可以直接使用 C/C++ 实现。
- 适合 ESP32-S3 这样的嵌入式处理平台。

如果这是数字信号处理相关课程设计，还可以实现 FFT 最大峰值法作为对照算法，比较两种算法的识别准确率。

## 五、数字信号处理流程

### 5.1 音频采集参数

建议初期采用以下参数：

| 参数 | 数值 |
| --- | ---: |
| 采样频率 | 16000 Hz |
| I2S 数据位宽 | 32 bit |
| 声道数 | 1 |
| 每帧采样点数 | 1024 |
| 帧移 | 512 |
| 最低识别频率 | 80 Hz |
| 最高识别频率 | 2000 Hz |
| YIN 初始阈值 | 0.15 |

一帧采样信号的时长为：

  1024
T=─────=64 ms
  16000

相邻帧采用 50% 重叠，可以提高音高变化时的响应速度。

### 5.2 信号预处理

采集到的音频先进行以下处理：

1. 数据格式转换：将 I2S 原始整数数据转换成浮点数据。
2. 去除直流分量：每个采样点减去当前帧均值。
3. 静音检测：计算信号 RMS，判断是否有足够强的声音输入。

RMS 的计算公式为：

$$
RMS=\sqrt{\frac{1}{N}\sum_{i=0}^{N-1}x_i^2}
$$

如果声音能量低于设定阈值，则不进行基频识别，直接输出无有效音符。

这一步非常重要，可以避免安静环境下屏幕持续显示随机音符。

基础版本暂时不需要复杂的降噪算法。

### 5.3 YIN 基频估计算法

YIN 的基本思想是：利用音频信号的周期性，寻找最合适的重复周期。

│ 输入一帧音频             │
│                          ├─────┐
└──────────────────────────┘     │
                                 │
                                 │
┌──────────────────────────┐     │
│ 计算差分函数             │     │
│                          ├◄────┘
│                          ├───────┐
└──────────────────────────┘       │
                                   │
                                   │
┌──────────────────────────┐       │
│ 累积均值归一化           │       │
│                          ├◄──────┘
│                          ├─────────┐
└──────────────────────────┘         │
                                     │
                                     │
┌──────────────────────────┐         │
│ 搜索满足阈值的局部最小值 │         │
│                          ├◄────────┘
│                          ├───────────┐
└──────────────────────────┘           │
                                       │
                                       │
┌──────────────────────────┐           │
│ 抛物线插值               │           │
│                          ├◄──────────┘
│                          ├─────────────┐
└──────────────────────────┘             │
                                         │
                                         │
┌──────────────────────────┐             │
│ 计算基频                 │             │
│                          ├◄────────────┘
│                          ├───────────────┐
└──────────────────────────┘               │
                                           │
                                           │
┌──────────────────────────┐               │
│ 输出频率及置信度         │               │
│                          ├◄──────────────┘
└──────────────────────────┘

第一步：计算差分函数

     W-1
d(τ)= ∑  (xⱼ-x_{j+τ})²
     j=0

其中：

- xⱼ 为音频采样值。
- τ 为延迟采样点数。
- W 为比较窗口长度。

对于本项目，可以取 W=512。

第二步：累积均值归一化

$$
d'(\tau)=
\begin{cases}
1 & \tau=0\\
\dfrac{\tau d(\tau)}
{\sum_{j=1}^{\tau}d(j)} & \tau>0
\end{cases}
$$

第三步：搜索基频周期

根据设定的识别范围，搜索延迟区间为：

     16000
τₘᵢₙ=─────=8
     2000

     16000
τₘₐₓ=─────=200
      80

在该区间寻找满足阈值条件的第一个局部最小值。

第四步：抛物线插值

由于真实周期可能不是整数个采样点，因此需要对局部最小值进行插值，得到更精确的周期 τ̂。

第五步：计算基频

   fₛ
f₀=──
   τ̂

例如，插值后检测到周期约为 36.36 个采样点，则：

   16000
f₀=─────≈440.04 Hz
   36.36

最终得到接近 A4 的基频。

### 5.4 识别结果平滑

为了避免显示的频率持续跳动，建议加入以下机制：

- 静音检测。
- YIN 置信度检测。
- 最近 3 帧有效频率的中值滤波。
- 有效性状态判断。

滤波不宜过强，否则会导致切换音符时响应迟缓。

## 六、音符识别与音高偏差计算

得到基频以后，剩下的工作主要是数学转换，不需要复杂的识别算法。

### 6.1 基频转换为 MIDI 音符编号

采用十二平均律，以 A4 = 440 Hz 为标准音。

$$
m=69+12\log_2\left(\frac{f_0}{440}\right)
$$

将计算结果四舍五入：

n=round(m)

即可得到最接近的 MIDI 音符编号。

### 6.2 音符编号转换为音名

| 余数（n % 12） | 音名 |
| ---: | --- |
| 0 | C |
| 1 | C# |
| 2 | D |
| 3 | D# |
| 4 | E |
| 5 | F |
| 6 | F# |
| 7 | G |
| 8 | G# |
| 9 | A |
| 10 | A# |
| 11 | B |

八度编号为：

        n
octave=⌊──⌋-1
        12

### 6.3 计算音高偏差

目标音符的标准频率为：

$$
f_{ref}=440\times2^{\frac{n-69}{12}}
$$

实际频率与标准频率之间的音分偏差为：

$$
cents=1200\log_2\left(\frac{f_0}{f_{ref}}\right)
$$

其中：

- 正数：音高偏高。
- 负数：音高偏低。
- 接近 0：音高准确。
- 100 Cent 等于一个半音。

例如：

| 检测频率 | 识别音符 | 音高偏差 |
| ---: | --- | ---: |
| 260.00 Hz | C4 | -10.8 Cent |
| 261.63 Hz | C4 | 约 0 Cent |
| 435.00 Hz | A4 | -19.8 Cent |
| 440.00 Hz | A4 | 0 Cent |
| 445.00 Hz | A4 | +19.6 Cent |
| 880.00 Hz | A5 | 0 Cent |

### 7.3 主程序运行逻辑

void loop() {
    // 1. 读取一帧音频
    readAudioFrame(samples);

    // 2. 预处理
    removeDC(samples);

    // 3. 判断是否有声音
    if (isSilence(samples)) {
        showNoSignal();
        return;
    }

    // 4. 估计基频
    PitchResult pitch = detectPitch(samples);

    // 5. 判断识别结果是否可靠
    if (!pitch.valid) {
        showNoSignal();
        return;
    }

    // 6. 转换为音符
    NoteResult note = frequencyToNote(pitch.frequency);

    // 7. 输出结果
    showNote(note);
}

这里是程序结构示意，并非完整的可烧录程序。基础版本可以先使用单循环结构，后续如果出现音频采集丢帧，再引入 FreeRTOS 多任务及双缓冲机制。

## 十二、最终推荐技术方案

| 技术环节 | 选型 |
| --- | --- |
| 主控 | ESP32-S3 |
| 麦克风 | INMP441 |
| 音频通信 | I2S |
| 开发环境 | PlatformIO + Arduino |
| 编程语言 | C++ |
| 采样率 | 16 kHz |
| 基频算法 | YIN + 抛物线插值 |
| 对照算法 | FFT 最大峰值法 |
| 稳定处理 | RMS 静音检测 + 中值滤波 |
| 音符识别 | 十二平均律 |
| 显示 | 串口 → SSD1306 OLED |

建议你们现在的第一个里程碑是：让 ESP32-S3 通过 INMP441 采集声音，并能够在串口实时输出正确的基频、音名和音分偏差。

只要实现了这个目标，课题的核心功能就已经成立，后续 OLED 接入和算法优化都可以在此基础上独立进行。
